    KYNOVA

    Un traductor para un lenguaje educativo imperativo, con palabras reservadas inspiradas en BioShock. Lee un archivo .kyn, lo analiza y lo traduce a Chapín.

    Visión general

    ¿Qué es Kynova?

    Un lenguaje de programación pequeño, hecho para el curso de Compiladores, y el programa que lo procesa.

    El lenguaje

    Se escribe en archivos .kyn. Es imperativo: declara variables, lee, imprime, decide con condicionales y repite con ciclos. El tema de BioShock es solo de vocabulario: la gramática es la de un lenguaje imperativo común.

    El programa

    Un ejecutable escrito en C11 llamado kynova. Revisa que el código esté bien escrito y bien tipado, y puede generar la traducción a Chapín (Chapin.gt).

    Para qué sirve

    Demuestra el front-end de un compilador: léxico, sintaxis, árbol del programa y tabla de símbolos, más un traductor a otro lenguaje del curso.

    El lenguaje

    Vocabulario de Kynova

    Cada palabra reservada tiene un equivalente en cualquier lenguaje imperativo.

    KynovaEquivale aQué hace
    splicedeclararDeclara una variable
    adamintTipo entero
    evereal / floatTipo decimal
    plasmidstringTipo texto. Solo guarda cadenas
    radioleer / inputEntrada por consola
    diarymostrar / printSalida en pantalla
    atlasifCondicional
    ryanelseRama alternativa. Es obligatoria
    ryan atlaselse ifCondicional encadenado
    vitawhileCiclo mientras

    Las palabras reservadas distinguen mayúsculas: atlas es reservada, Atlas es un identificador cualquiera.

    El lenguaje

    Cómo se escribe un programa

    Un programa es una lista de instrucciones. Cada una termina en ; y los bloques van entre llaves.

    splice adam age;
splice adam laps = 1;
splice eve average;
splice plasmid nombre = "Jack";

radio(age);
radio(average);

atlas (age >= 18) {
    diary(average + 5.0);
} ryan {
    diary(0);
}

vita (laps <= 3) {
    diary(laps);
    laps = laps + 1;
}
    • Operadores aritméticos: + - * /. Relacionales: < > <= >= == !=.
    • Los paréntesis agrupan. La condición de atlas y vita va siempre entre paréntesis.
    • Los relacionales no se encadenan: a < b < c es un error de sintaxis.

    El lenguaje

    Tipos de datos

    adam

    Entero. Equivale a int en C11.

    Ejemplo: splice adam laps = 1;

    eve

    Real. Equivale a double en C11.

    Ejemplo: splice eve average = 5.0;

    plasmid

    Texto. Una cadena entre comillas dobles, en una sola línea.

    Ejemplo: splice plasmid nombre = "Jack";

    Reglas de conversión

    • eve acepta adam: guardar un entero en una variable real está permitido.
    • adam no acepta eve: se perdería la parte decimal, así que es error.
    • En una operación, si algún operando es eve el resultado es eve. Si ambos son adam, el resultado es adam.
    • plasmid solo acepta cadenas. No se suma, no se compara y no se lee con radio. adam y eve no aceptan cadenas.

    El lenguaje

    Comentarios

    El lexer los descarta, así que no llegan al parser.

    // comentario de una línea

/* comentario
   de varias líneas */

    Un /* sin su */ produce el error léxico "comentario multilínea sin cerrar (falta '*/')". Hay una prueba para ese caso: 09_comentario_sin_cerrar.kyn.

    Cómo funciona

    El recorrido de un programa

    El archivo pasa por varias fases. Cada una recibe la salida de la anterior.

    Archivo .kynTexto fuente
    →
    FlexLexer: agrupa letras en tokens
    →
    BisonParser: revisa la gramática y arma el AST
    →
    SemánticaRecorre el AST, llena la tabla de símbolos y valida tipos
    →
    ChapínOpcional: escribe Chapin.gt
    • Token: la unidad mínima, por ejemplo splice, un número o un ;.
    • AST (árbol de sintaxis abstracta): el programa como árbol, sin paréntesis ni ; que ya no hacen falta.
    • Tabla de símbolos: la lista de variables con su tipo, alcance, línea y usos. En el proyecto se llama Gene Bank.

    Las fases corren en orden: si hay errores léxicos o sintácticos, el programa se reporta como inválido.

    Fase 1 · src/kynova.l

    Flex: el análisis léxico

    Convierte el texto en una lista de tokens, cada uno con su línea y columna.

    • Reconoce las palabras reservadas, identificadores [a-zA-Z_][a-zA-Z0-9_]*, enteros, reales y cadenas.
    • El real [0-9]+\.[0-9]+ se reconoce antes que el entero [0-9]+.
    • Los operadores de un carácter se devuelven como el propio carácter ('+', ';'). Los de dos caracteres tienen token propio: LE, GE, EQ, NE.
    • Descarta espacios y comentarios.
    • Cada token guarda su posición para los mensajes de error.

    Ver los tokens

    ./kynova --tokens tests/valid/01_demostrativo.kyn

Lín:Col   Token          Lexema
2:1       SPLICE         splice
2:8       ADAM           adam
2:13      ID             age
2:16      PUNTO_COMA     ;
...
Total: 66 tokens

    Fase 1 · errores

    Errores léxicos

    El lexer da un mensaje específico para cada caso.

    ErrorEjemplo
    Identificador que empieza con dígitosplice adam 2age;
    Real con coma80,5 en lugar de 80.5
    Real sin parte fraccionaria3.
    Comentario multilínea sin cerrar/* nunca termina
    Cadena sin cerrar"hola
    Carácter no reconocidoun símbolo que el lenguaje no usa

    En los tres primeros el lexer reporta el error pero devuelve igual un token razonable (ID o REAL). Así el parser no genera errores en cascada.

    Fase 2 · src/kynova.y

    Bison: el análisis sintáctico

    Revisa que los tokens sigan la gramática del lenguaje y construye el AST mientras lo hace.

    • La gramática sigue la EBNF del contrato del curso.
    • La precedencia está en la estructura expresion → termino → factor, sin usar %left. Así 2 + 3 * 4 = 14.
    • La recursión por la izquierda da asociatividad de izquierda a derecha: 20 - 5 - 3 = 12.
    • ryan es obligatorio: la regla de atlas exige bloque RYAN bloque.
    • Los relacionales solo aparecen en condicion, por eso no se pueden encadenar.
    • Los paréntesis de agrupación no crean nodo: la forma del árbol ya los representa.
    • La gramática no tiene conflictos shift/reduce ni reduce/reduce.
    • Los mensajes de error salen en español gracias a %define parse.error custom. Por eso hace falta Bison 3.6 o superior.

    Recuperación de errores

    Con reglas como error ';' y error bloque, el parser sigue después de un error y reporta varios en una sola corrida.

    Fase 2 · src/ast.h, src/ast.c

    El AST

    Un nodo por cada construcción del lenguaje. Cada nodo guarda su línea y columna.

    NodoRepresenta
    PROGRAM, BLOCKEl programa y cada bloque { }
    DECLsplice: declaración, con valor inicial opcional
    ASSIGNAsignación
    READ, WRITEradio y diary
    IF, WHILEatlas / ryan y vita
    BINOP, RELOP+ - * / y < > <= >= == !=
    INT, REAL, STR, IDLiterales e identificadores

    El análisis semántico anota en cada expresión su tipo (adam o eve), y se ve al imprimir el árbol.

    Fase 2 · salida

    Un AST de ejemplo

    Es lo que muestra ./kynova --ast para el programa demostrativo.

    Programa (7 instrucciones)
├── Declaración splice adam age  [línea 2]
├── Declaración splice adam laps  [línea 3]
│   └── valor inicial: Entero 1 : adam
├── Declaración splice eve average  [línea 4]
├── Entrada radio(age)  [línea 6]
├── Entrada radio(average)  [línea 7]
├── Condicional atlas/ryan  [línea 9]
│   ├── cond: Comparación '>='
│   │   ├── Identificador age : adam
│   │   └── Entero 18 : adam
│   ├── atlas: Bloque (1 instrucción)
│   └── ryan: Bloque (1 instrucción)
└── Ciclo vita  [línea 16]
    ├── cond: Comparación '<='
    └── cuerpo: Bloque (2 instrucciones)

    Con Graphviz instalado, make ast-png genera ast.png, el mismo árbol como imagen. Las instrucciones salen en dorado, los bloques en azul y las expresiones en crema.

    Fase 3 · src/symtab.c, src/semantic.c

    La tabla de símbolos: Gene Bank

    Registra cada variable con todo lo que el compilador necesita saber de ella.

    #    Nombre           Tipo  C11     Alcance     Línea   Usos
---  ---------------- ----- ------- ----------- ------- ----
1    age              adam  int     global      2       2
2    laps             adam  int     global      3       3
3    average          eve   double  global      4       2
    • Alcance: el programa es el alcance global. Cada bloque { } abre uno nuevo, y las variables declaradas dentro dejan de existir al cerrarlo.
    • C11: el tipo equivalente en C, como preparación para generar código más adelante.
    • Usos: cuántas veces se referencia la variable.

    Se ve con ./kynova --symbols.

    Fase 3 · src/semantic.c

    Validaciones semánticas

    El parser acepta la forma. La semántica revisa que el programa tenga sentido.

    Errores

    • Variable usada sin declarar, o fuera de su alcance.
    • Declaración duplicada en el mismo alcance.
    • Asignar eve a una variable adam.
    • Mezclar plasmid con números: sumarlo, compararlo, leerlo con radio o guardar una cadena en adam o eve.

    Advertencias

    No invalidan el programa.

    • Variable declarada pero nunca usada.
    • División entre la constante cero.

    Detalle: en splice adam x = x + 1; la x del lado derecho todavía no está declarada, así que da error.

    Extra · src/chapin.c

    Traductor Kynova → Chapín

    Recorre el AST ya validado y escribe el mismo programa en la sintaxis de Chapín.

    KynovaChapín
    splice adamva pisto
    splice eveva quetzal
    splice plasmidva (tipo genérico)
    atlascabal
    ryansino
    ryan atlassino con cabal anidado
    vitabrega
    radioclavar
    diaryshute
    ./kynova -c Chapin.gt programa.kyn

    Como el AST no guarda paréntesis, el traductor los repone según la precedencia y la asociatividad izquierda.

    Extra · ejemplo real del repositorio

    Un programa y su traducción

    Chapín (Chapin.gt)

    va pisto vidas = 0;
va quetzal puntos = 0.00;
vidas = 5;
puntos = 10.30;
clavar(puntos);
cabal (vidas >= 5) {
    puntos = puntos + 10.50 * 2;
} sino {
    vidas = 0;
}
shute(puntos);
brega (vidas < 10) {
    vidas = vidas + 1;
}

    Kynova (salida.kyn)

    splice adam vidas = 0;
splice eve puntos = 0.00;
vidas = 5;
puntos = 10.30;
radio(puntos);
atlas (vidas >= 5) {
    puntos = puntos + 10.50 * 2;
} ryan {
    vidas = 0;
}
diary(puntos);
vita (vidas < 10) {
    vidas = vidas + 1;
}

    Los dos archivos están en la raíz del repositorio. salida.kyn se generó desde Andante, otro lenguaje del curso.

    Cómo se corre

    Requisitos e instalación

    • Compilador de C con soporte C11 (gcc o clang).
    • Flex 2.6 o superior.
    • GNU Bison 3.6 o superior. Se usa %define parse.error custom para los mensajes en español.
    • make.

    macOS

    El Bison que trae macOS (2.3) es muy viejo.

    brew install bison flex

    El Makefile detecta las versiones de Homebrew solo.

    Linux (Ubuntu/Debian)

    sudo apt install build-essential flex bison

    Windows

    Usar WSL (Ubuntu) y seguir los pasos de Linux.

    Cómo se corre

    Compilar

    make          # genera el ejecutable ./kynova
make clean    # borra build/ y el ejecutable

    Si Bison o Flex están en otra ruta:

    make BISON=/ruta/a/bison FLEX=/ruta/a/flex

    Qué hace make, paso a paso

    bison -d -o build/kynova.tab.c src/kynova.y   # parser + tokens
flex -o build/lex.yy.c src/kynova.l           # lexer
cc -std=c11 ... -o kynova build/*.o           # enlaza con main, ast, symtab, semantic, chapin

    Bison va primero porque genera kynova.tab.h, la lista de tokens que Flex necesita.

    Cómo se corre

    Ejecutar

    ./kynova [opciones] archivo.kyn
    OpciónMuestra
    -t, --tokensFlujo de tokens reconocidos por Flex
    -a, --astAST construido por Bison, anotado con tipos
    -s, --symbolsTabla de símbolos (Gene Bank)
    -d, --dot ARCHExporta el AST en formato Graphviz
    -c, --chapin ARCHGenera la traducción a Chapín
    -q, --quietSolo errores y el resultado final
    -h, --helpAyuda

    Sin opciones se muestran el AST y la tabla de símbolos.

    Código de salida

    • 0: programa válido.
    • 1: hay errores léxicos, sintácticos o semánticos.
    • 2: error de uso, como un archivo inexistente o una opción desconocida.

    Pruebas

    • tests/valid/*.kyn deben terminar con código 0. Hay 5 programas.
    • tests/invalid/*.kyn deben terminar con código 1, y el mensaje debe contener el texto de su primera línea // ESPERADO: .... Hay 18 programas.
    FaseCasos inválidos que prueba
    Léxicaidentificador con dígito, real con coma, comentario sin cerrar, cadena sin cerrar
